# コード品質

## 検査の方針

`npm run check` をローカル・CI 共通で使い、機械判定できる規約は自動検査で強制する。
検査一覧とツールの固定版は [package.json](/package.json)、実行方法は [開発と検証](/docs/development.md) を参照する。
検査違反・解析失敗・対象なし・必要ツールの不足は非ゼロ終了にする。
Mutation testing と実行・集計・スコア判定などの関連機構は導入しない。

## 行数・Lint・状態の網羅性

- 実装は600行以上で警告、1,000行以上でエラー。空行・コメント・改行のない末尾行を含む物理行数で数え、テストと生成物は除外する。
- 責務で分割し、コメント削除や処理の詰め込みで上限を回避しない。分割できない場合だけ先頭コメントに `linelint:allow-long -- 理由` を書く。
- `oxlint-*`・互換形式の `eslint-*` 抑制には規則名と `-- 理由` を必須とし、一括抑制は禁止する。再有効化にも規則名が必要だが理由は不要。不要な抑制はエラーにする。
- 関数の複雑度は40以下。テストと生成型は除外する。
- `Verdict` は `satisfies Record<…>`、公開モードは網羅的 switch と `never` で漏れを防ぐ。`phase` は既存状態だけの union 型にする。

## 依存境界と Mods API

本体の API 操作は `plugins/cerberus-gate/hooks/register.ts` に集約する。
許可 API・引数・import の静的な制約は [architecture.ts](/scripts/quality/architecture.ts) を正とし、変更時は次の境界を維持する。

| 対象                                   | 依存・操作の境界                                                                                                           |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 本体の `hooks/register.ts`             | hooks 内のモジュールと `claude-code` の型 import                                                                           |
| その他の本体モジュール                 | hooks 内だけ。登録用モジュールと Node ヘルパーへの import は禁止                                                           |
| `hooks/session-log.mts`                | 検証資料に必要な Node 組み込み関数と `debug-log.mts`・`debug.ts` の import を例外とする                                    |
| `hooks/debug-log.mts`                  | 専用保存に必要な Node 組み込み関数の名前付き import、自プラグインの `plugin.json` と `debug.ts` の import だけを例外とする |
| 描画用プラグインの `hooks/register.ts` | `claude-code` の型 import だけ。実行時依存とエンジン API 呼び出しは禁止                                                    |

ヘルパーは標準 JSONL を読み取り専用で開き、書き込みは自身の私有一時ディレクトリと専用デバッグ領域内に限定する。
`session-log.mts` から `debug-log.mts` への依存は、生成した3資料の保存に限って認める。
原文・業務ファイルの不変性と対象外削除の拒否をテストで確認する。

- `process.run` は `node`、同梱ヘルパー、操作の3引数だけ。
  `session-log.mts` は `create`・`release`、`debug-log.mts` は `initialize`・`append` に限定する。オプションは `stdin`・`timeoutMs` のみとし、任意コマンド・shell・環境変数・cwd の変更を許可しない。
- 状態の保存・設定の変更は自分のプラグインの用途に限定し、他のプラグインやホスト全体へ権限を広げない。
- 静的な `tool.call` は `TaskStop`、エージェント登録・起動は既存レビュアーだけ。対象をリテラルか一意な定数から解決できなければ拒否する。
- モデルが選ぶツール呼び出しは `callReviewTool` に集約し、提示済みの一覧と照合して検査済みの引数だけを転送する。実行時の `tool.call`・`tool.check` は審査継続中かを確認し、制御フィールドを拒否して通常の権限判定を通す。`tool.check` では本体の判定を拒否の区別のために記録するだけで、書き換えない。
- API の別名参照・計算プロパティ・間接コード読み込みは禁止。エンジン引数は `$`・`_$` とし、直接呼び出しか `EngineInterface` を受け取るローカル関数への受け渡しに限る。

静的検査は副作用禁止の保証ではない。
全ツールの提示・権限拒否・制御フィールド拒否をテストし、プロンプトによる制限は [回答検証の仕組み](/docs/answer-gate.md#調査と権限) に従う。

## 文書と検査ツール

手書きの `docs/` 文書は AGENTS.md の「docs インデックス」に掲載する。
検査ツールは固定版を使い、ネイティブ配布物は公式配布元と SHA-256 を確認してローカルキャッシュに置く。
グローバル環境は変更せず、取得失敗では停止する。
仮想モジュールの除外は個別指定に限り、未使用コードや依存を一括で検査対象外にしない。

## テストとカバレッジ

検査数のためのテストより、公開条件・副作用の境界が破られたときに失敗するテストを優先する。
カバレッジは本体と検証資料ヘルパーを含め、Node テストを重複実行せず計測する。
Claude Code 独自ランナーの結果とは分けて扱う。
割合の閾値は設けず、テスト失敗は非ゼロ終了にする。
