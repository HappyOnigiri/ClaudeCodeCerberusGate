# コード品質

## 採用方針

- Lint などのコード品質検査には TypeScript に適したツールを使う。
- Mutation testing と、その実行・集計・スコア判定などの関連機構は導入しない。
- 行数チェックなどの基本的な品質検査を導入する。
- 機械的に判定できる規約は自動検査で強制する。検査の入口を共通化し、ローカルと CI で検査一覧が食い違わないようにする。

## 行数チェック

- 実装ファイルは 600 行以上で警告、1,000 行以上でエラーとする。
- 空行・コメントを含む物理行数を数え、末尾に改行のない最終行も 1 行とする。
- テストファイルと生成物は対象外とする。
- 責務ごとに分割する。コメントの削除や処理の詰め込みによって上限を回避しない。
- 分割できない場合だけ、ファイル先頭のコメントに `linelint:allow-long -- 理由` を記載して例外を認める。理由のない例外はエラーとする。

## 共通の検査

`npm run check` をローカルと CI の共通の入口とする。
フォーマット、Lint、型チェック、行数、依存境界、抑制コメント、Markdown、workflow、Shell、未使用コード、プラグイン検証、テスト、カバレッジを実行する。
検査違反、解析失敗、対象なし、必要ツールの不足は非ゼロ終了にする。
本体の TypeScript はエンジンが直接読むため、型チェックとプラグイン検証でロード可能な構成を確認する。

## 依存境界と Mods API

本体の API 操作は `hooks/register.ts` に集約する。
依存できる対象は次のとおり。

| 本体モジュール     | 許可する依存先                           |
| ------------------ | ---------------------------------------- |
| 登録用モジュール   | hooks 内のモジュール、`claude-code` の型 |
| その他のモジュール | hooks 内の登録用モジュール以外           |

登録用モジュールでも、外部への依存は `claude-code` の型 import に限る。
生成型、テスト、検証スクリプト内の文字列 fixture は依存境界の検査対象外とする。

許可する API は次の18種類とする。

- `agent.list/register/spawn`
- `clock.now/after`
- `command.register`
- `config.set`（自分の `reviewerModel` 設定のみ）
- `prompt.submit`
- `session.messages/version`
- `state.get/set`（自分の再ロード復元用の状態のみ）
- `tool.list/call`
- `ui.status/open/close/resolve`

`state.get/set` の対象は `plugin: "cerberus-gate", key: "recovery"` に限定する。
`tool.call` は `TaskStop` だけ、エージェント登録・起動は既存のレビュアーだけに限定する。
対象はリテラルまたは一意な定数参照から解決し、解決できなければ拒否する。
API の別名参照、計算プロパティ、間接的なコード読み込みも拒否する。
エンジン引数は `$` または `_$` とし、直接呼び出しか、`EngineInterface` を受け取るローカル関数への受け渡しに限る。
これは静的な使用箇所の検査であり、実行時の読み取り専用ガードと権限テストも維持する。

## Lint と状態の網羅性

`oxlint-*` と互換形式の `eslint-*` の抑制には具体的な規則名と `-- 理由` を必須とする。
全規則の一括抑制は禁止し、再有効化にも規則名を必須とする。
再有効化の理由は不要とする。
行・ブロックコメントを構文解析し、文字列を抑制コメントと誤認しない。
不要な抑制は Oxlint でエラーにする。

関数単位の複雑度は40以下とする。
テストと生成型は複雑度検査の対象外とする。
`Verdict` の判定は `satisfies Record<…>`、公開モードの制御は網羅的な switch と `never` で処理漏れを防ぐ。
`phase` は既存の状態だけを許す union 型にする。

## 文書・workflow・Shell・未使用コード

手書きの `docs/` 文書を AGENTS.md の「docs インデックス」に掲載する。
Markdown の構文解析結果から、ルート相対・文書相対・参照形式のローカルリンクを検査する。
URL エンコードを復元し、リンク切れとリポジトリ外への参照を拒否する。
外部 URL の疎通と見出しアンカーの存在確認は対象外とする。

workflow は actionlint 1.7.12、シェルスクリプトと拡張子のない Git hook は ShellCheck 0.11.0 で検査する。
固定した公式配布物の SHA-256 を検証してローカルキャッシュへ導入し、グローバル環境を変更しない。
macOS と Linux の arm64・x64 をサポートする。
配布 URL とチェックサムは `scripts/quality/native-tools.json` に記録する。

未使用ファイル・export・依存関係は Knip 6.43.0 で検査する。
Hook 登録、Markdown カスタム規則、テスト、npm スクリプトからの実行経路を解析対象にする。
仮想モジュールの除外は未宣言依存の `claude-code`・`claude-code/testing` と、未解決参照の `claude-code`・`claude-code-tools` の個別指定に限る。

## カバレッジ

Node 24 以降の標準機能で、本体の行・分岐・関数のカバレッジを計測する。
既存の Node テストを一度だけ実行し、要約と `tmp/coverage/lcov.info` を出力する。
CI は LCOV を artifact として保存する。
Claude Code 独自ランナーのテスト結果は別に扱い、カバレッジには含めない。
割合による合否判定は設けず、テスト失敗はそのまま非ゼロ終了にする。

カバレッジの閾値と実装・テストの一対一対応は今後の検討対象とする。
検査の数を増やすためのテストではなく、公開条件と副作用の境界が破られたときに失敗するテストを優先する。
