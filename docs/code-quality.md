# コード品質

## 採用方針

- Lint などのコード品質検査には TypeScript に適したツールを使う。
- Mutation testing と、その実行・集計・スコア判定などの関連機構は導入しない。
- 行数チェックなどの基本的な品質検査を導入する。
- 機械的に判定できる規約は自動検査で強制する。検査の入口を共通化し、ローカルと CI で検査一覧が食い違わないようにする。

## 行数チェック

- 実装ファイルは 600 行以上で警告、1,000 行以上でエラーとする。
- 空行・コメントを含む物理行数を数え、末尾に改行のない最終行も 1 行とする。
- テストファイルと生成物は対象外とする。
- 責務ごとに分割する。コメントの削除や処理の詰め込みによって上限を回避しない。
- 分割できない場合だけ、ファイル先頭のコメントに `linelint:allow-long -- 理由` を記載して例外を認める。理由のない例外はエラーとする。

## 導入した検査と今後の検討

`npm run check` にフォーマット、Lint、型チェック、行数、Markdown、プラグイン検証、テストを接続している。
ツールのバージョンは package.json とロックファイルで固定する。
本体の TypeScript はエンジンが直接読むため、型チェックとプラグイン検証でロード可能な構成を確認する。

未使用コードの追加検査、カバレッジの閾値、実装とテストファイルの対応、コメントの独自検査は今後具体化する。
検査の数を増やすためのテストではなく、公開条件と副作用の境界が破られたときに失敗するテストを優先する。
