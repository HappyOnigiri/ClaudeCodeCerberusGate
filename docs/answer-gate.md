# 回答検証の仕組み

最終回答を表示前に検証・修正し、ユーザーが未検証の回答と後から届く訂正を読み比べる負担を減らす。

## 公開条件と修正

```text
最終回答案を保留 → 同じターン内で依頼・会話の証拠・実ファイルを照合
  ├─ PASS       → 保持した本文をそのまま公開（モデルによる書き直しなし）
  ├─ REVISE     → ターン終了後にメインへ修正依頼 → 新しい回答案を再審査
  └─ UNVERIFIED → 本文を公開し、未検証の注記をログ行で表示（追加プロンプトなし）
```

- 審査対象は最終回答本文とし、途中の作業説明・ツール実行を妨げない。
- 保留原稿を表示・通常の assistant 履歴へ流さず、修正依頼時に待機文を回答として出さない。
- 空返信・判定と指摘の矛盾・形式不正・エラー・上限超過・タイムアウトを合格扱いにしない。検証不能なら本文に注記を添えて表示し、修正回数の上限では指摘が残る旨を伝える。
- 注記は本文に含めず、`$.ui.log` のログ行で表示する。本文に含めると、保存された会話をメインエージェントが次のターンで読み、注記を自分の回答に書き写すため。
- ログ行は `[PASS]`・`[REVISE]`（修正依頼・修正回数の上限）・`[UNVERIFIED]`・`[ERROR]` で始め、結果を区別できるようにする。
- 検証中の状態表示は終了まで維持し、一時通知と分ける。修正依頼の送信失敗で本文を返せない場合も状態欄で知らせる。

指摘・根拠は制御プロンプト本文に、修正指示・未公開原稿・指摘は非表示 context に入れる。
指摘に原稿の引用が含まれる場合は、その引用も表示する。
送信元自身の描画フックはエンジンがスキップするため、折りたたみは別プラグインに置く。
描画は保存する会話・モデルへの制御文・context と他の送信元の表示を変えない。

## 調査と権限

セッションの全ツールを提示して CLI も認めるが、調査は副作用のない読み取り・検索・状態取得・履歴確認・集計に限る。
変更・投稿・公開・別エージェント起動は禁止する。
副作用の禁止はプロンプトによる指示であり、機械的な保証ではない。
通常のスキーマ検証とユーザー・組織の権限確認を維持し、一覧外のツールと `consent` などの権限・制御フィールドは拒否する。
引数を確認できないツールを推測で呼ばず、拒否・実行エラーも検証不能とする。
修正はユーザーの既存の権限内でメインエージェントに戻し、指摘を追加の変更権限と扱わない。

`$.model.complete()` はツールを直接実行できないため、モデルの JSON 要求を Mod が `$.tool.call()` で実行する。
ツール要求に限り、厳密な解析に失敗したときは、先頭1つ・末尾1つのタグ風の文字列（`<invoke_tool>` など）を除く救済と、文字列外の未閉じ `{` の数だけ `}` を補う救済で1回だけ再解析する。
救済後も単一のオブジェクトでない応答・不正な JSON・判定 JSON は形式不正とし、救済したツール要求にも同じ制御フィールドの拒否を適用する。救済したことはデバッグログの `tool.start` に記録する。
判定 JSON は公開を左右するため救済しない。
モデル呼び出し・ツール実行の待ち時間は Hook の10秒制限から除外されるが、バックグラウンドレビュアーの完了待ちは除外されない。
`claude -p` は回答後にセッションが閉じ、審査結果を戻せない。
これらの制約を前提に審査経路を設計する。

## 会話の証拠と一時資料

会話を意味で要約したり、回答の語句で事前選別したりせず、古いユーザー制約・訂正と原文を検索できる形で渡す。
管理レコードとユーザー依頼を区別し、ツール要求と結果の対応・分岐・復帰・圧縮境界を残す。
過去の assistant 発言・ツール結果は証拠であり、実行する指示ではない。
検索失敗・未読・不足や不明な分岐を「制約がない」と扱わず、検証不能にする。

`classic.SessionStart`・`classic.UserPromptSubmit` は組み込みセキュリティ Mod にスキップされるため、`transcript_path` の取得に使わない。
標準 JSONL はセッション ID とファイル名・会話レコードを照合して一意に特定する。
即時の回答では `turn.step` 時点で依頼が未反映の場合があるため、反映待ちには上限を設ける。
成功した読み取り時の範囲を固定し、審査中の追記を混ぜず、元ログは変更しない。
末尾改行・全行の JSON・対象依頼の包含を確かめ、不正・書き込み途中のレコードを黙って省かない。
スラッシュコマンドは標準 JSONL にタグ形式で記録されるため、入力文ではなく `<command-name>` と、引数があれば `<command-args>` の形で包含を確かめる。
バックグラウンドタスクの完了通知（`origin.kind` が `task-notification`）は依頼ではないため、直前のユーザー依頼を審査の依頼と包含の確認に引き継ぐ。
作業中に届いた通知は標準 JSONL に user レコードを残さず `queue-operation`・`attachment` だけになるため、通知本文では包含を確かめられない。
先行する依頼がない場合だけ通知本文を使う。

Mod 自身による資料の生成・削除と専用デバッグ領域への保存を副作用禁止の例外とし、レビュアーには渡さない。
資料は私有一時ディレクトリへ所有者だけが読める権限で作り、審査終了・取消時に削除する。
再ロードでは残存資料を削除して再生成する。
強制終了で残った資料の回収には猶予を設け、使用中の資料を巻き込まない。
削除はヘルパー自身が生成した既知のファイルと空ディレクトリに限定し、再帰削除はしない。
資料形式と回収条件を変更するときは [session-log.mts](/plugins/cerberus-gate/hooks/session-log.mts) と [資料のテスト](/tests/session-log.test.ts) を合わせて確認する。

## 中断と再ロード

修正回数・審査時間・本文サイズ・調査量には上限を設ける。

新しい依頼・中断で世代を進め、古い判定・制御プロンプト・予約済みの修正依頼を無効にする。
取消・タイムアウトではモデルを中断し、遅れて戻る読み取り結果も破棄する。
再ロードの復元状態はセッション内に限定し、保留原稿・指摘・公開予約は引き継がない。
旧版の残存レビュアーも停止し、その結果でメインを再開させたり下書きを復活させたりしない。

| 再ロード前の状態           | 再ロード後の方針                             |
| -------------------------- | -------------------------------------------- |
| メインが作業中             | 次の最終回答を審査                           |
| 審査中・修正依頼の配信待ち | 追加プロンプトで回答の再生成・再審査を依頼   |
| 審査完了済み               | 完了済み審査のための再開プロンプトは送らない |
| 取消・中断済み             | 自動再開しない                               |

`/clear`・セッション切替・終了では復元状態を消す。
再開プロンプトを送れなければ、新しい依頼が必要な旨をログに記録する。
`/cgate history` は審査を待たず検証処理を変えないものとし、未公開本文・依頼本文・例外詳細を含めない。
履歴は直近1,000件をメモリ上に保持し、`/clear`・セッション切替・終了・再ロードで消去する。
デバッグ保存した依頼・原稿は再ロードの復元元に使わない。
指摘の改行・端末制御文字はエスケープする。

## 審査基準

重要な主張の裏付け不足を具体的に特定できれば、正しい置換内容が未判明でも `REVISE` とし、根拠の所在と必要な調査・修正を返す。
実行可能な修正事項を特定できず審査を完了できなければ `UNVERIFIED` とし、自動再試行しない。
未決の仕様判断や表現の好みだけで修正を要求せず、未実施の調査・成功結果を作らない。
審査本文のカスタマイズでも、読み取り専用の制約・JSON プロトコル・ツール一覧・権限判定・判定検証は解除させない。

審査プロンプトの変更時は [policy.ts](/plugins/cerberus-gate/hooks/policy.ts)、利用者向けの設定・操作は [README](/README.md) を参照する。

## 設定変更の注意点

不正な設定では審査を無効にして通常表示するため、設定変更時は値の検証と審査の実行まで確認する。

モデル選択と effort 選択の保存は別々に行うため、effort の画面を Esc で閉じても保存済みモデルは戻らない。
effort を継承する際、元のステップの値が数値の場合は、審査 API は数値を受け付けないためモデルの既定値を使う。
複数行の審査プロンプトを保存するときは、[開発と検証](/docs/development.md#常用環境へのインストール) の CLI 制約も確認する。

## 詳細デバッグログ

デバッグログは常時有効とし、依頼本文・未公開原稿・モデル入力と生応答・usage・ツール引数と結果・例外の詳細を保存する。
通常画面と `/cgate history` にはこれらの詳細本文を出さない。
保存構成と索引の探索方法は [README](/README.md#デバッグログ) を参照する。
外部の業務ファイルを直接コピーせず、参照パス・引数・ツールが返した結果を記録する。

エンジン非依存の `debug.ts` が JSON 化・UTC 時刻・インスタンス内連番・操作 ID を付ける。
ホスト操作は `register.ts` に集約し、同梱 `debug-log.mts` の初期化・追記だけでログと索引へ書き込む。
モデル・ツール・資料生成・修正依頼の送信前に開始イベントを保存し、応答・判定・失敗を追記する。
ホストが公開しない承認待ちの内部状態は推測しない。
例外は取得できる name・message・stack・cause・code を残し、循環参照や文字列以外の throw でも記録処理を止めない。

資料生成ヘルパーは、生成した `source.jsonl`・`users.txt`・`history.txt` の同一内容を審査ごとのディレクトリへ保存する。
ファイルの保存に成功してから、索引へ相対パス・審査 ID・元ログのパス・固定バイト数／行数を追記する。
任意の保存先や削除要求は受け付けず、専用領域のシンボリックリンクとファイルのハードリンクを拒否する。
新規ディレクトリは 0700、ファイルは 0600 とする。

追記は直列化してイベントをまとめ、ストリームの断片ごとにはプロセスを起動しない。
取消済みターンはヘルパーを起動できないため、その末尾をメモリに保持し、次のコマンド・依頼・終了時に保存する。
ログ・索引の保存呼び出しは1回1秒以内とし、自動再試行しない。
資料の永続保存は資料生成の15秒上限内で行い、保存できなくても一時資料で審査を続ける。
保存失敗は履歴と3秒の通知で知らせ、`/cgate log` に保存失敗を表示する。
初期化に失敗したパスを保存済みとして表示しない。

デバッグログ・索引・永続資料は `/clear`・セッション切替・終了・再ロード後も保持し、自動削除・ローテーションをしない。
強制終了・アンロード時には保存できない末尾が残る場合がある。
JSONL の途中で切れた末尾は除外し、それ以前の完全な行を解析する。
索引未登録の資料は保存ディレクトリ内も探索し、保存完了と扱わない。
