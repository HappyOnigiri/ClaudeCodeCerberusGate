# 回答検証の仕組み

## 表示と修正の流れ

```text
メインの最終回答案
  → turn.step で本文を保持（画面には審査中の状態だけを表示）
  → 同じターン内で審査用モデルが依頼・会話の証拠・実ファイルを照合
      ├─ PASS       → 保持した本文をモデルに書き直させず、そのターンで公開
      ├─ REVISE     → 制御プロンプトの非表示 context に指摘と未公開原稿を添付
      │                → メインが修正 → 新しい最終回答案を審査
      └─ UNVERIFIED → 注記を付けて本文をそのターンで表示（追加プロンプトなし）
```

審査中は元の `turn.step` を保持し、状態欄で進行を表示する。
検証中の表示には時間による自動消去を適用せず、検証終了まで維持する。
設定結果やエラーなどの一時通知には、Claude Code の自動消去付き通知（`ui.toast`）を使い、表示時間を3秒に指定する。
通知の表示・消去は検証中のステータス表示に影響しない。
ポインターを通知に重ねている間や、通知を保留する画面を開いている間は、ホストの仕様に従って消去を待つ。
合格・検証不能時は追加ターンを作らず、保留していた本文を返す。
修正依頼を送るときは回答本文を空にし、待機文を回答として表示しない。
下書きの断片は表示・通常の assistant 履歴へ流さない。
ツール実行を伴うステップはメインの作業を続けるために通す。審査対象は最終回答本文であり、途中の作業説明ではない。

## 調査ツールと権限の境界

審査は `$.model.complete()` で行う。
この API はツールを直接実行できないため、審査用モデルが JSON でツール名と引数を要求し、Mod が `$.tool.call()` で実行して結果を戻す。
モデルには元の依頼・未公開原稿・作業ディレクトリ・検索用ログのパス・セッションの全ツールの説明と調査結果を渡し、通常のメイン履歴へ審査応答を追加しない。
モデル呼び出しとツール実行の待ち時間は Hook 自体の10秒制限から除外される。
単にバックグラウンドのレビュアーの完了を待つ方式は、この制限にかかるため使わない。

`$.tool.list()` が返す組み込み・MCP ツールをすべて提示する。
書き込み能力のあるツールも一覧に含むが、副作用のない読み取り・検索・状態取得・履歴確認・集計だけに使うようレビュープロンプトで指示する。
CLI の利用を認め、ファイルや設定の変更、投稿・公開、別エージェントの起動などを禁止する。
副作用の禁止はモデルへの指示であり、Mod が機械的に保証するものではない。

組み込みツールには、対象版の保存済み型定義から生成した引数の型情報を添える。
一覧 API は入力スキーマを返さないため、MCP などの引数は説明や利用可能な探索ツールから確認させる。
必要な引数を確認できなければ推測で呼ばず、検証不能とする。
スキーマの検証と、ユーザーや組織の権限確認・確認ダイアログは通常のエンジン経路に従う。
モデルからの `consent` などの権限・制御フィールドの指定は拒否し、一覧にないツールも実行しない。
拒否・エラーは合格と扱わず検証不能にする。
旧 `readOnlyMcpTools` 設定は廃止し、保存済みの値が残っていても無視する。

通常の審査では修正が必要な場合だけ追加プロンプトを送り、本文に指摘と根拠を表示する。
メインへの修正指示と未公開原稿・指摘は非表示の context にも添付し、未公開原稿そのものは表示用の本文に含めない。
ただし、審査の指摘に原稿からの引用が含まれる場合は、その引用も表示する。
`cerberus-gate-display` を併用すると、ターミナルの通常表示では制御プロンプト本文を折りたたみ、送信元の見出しだけを残す。
Ctrl+O で会話全体の詳細表示に切り替えると制御プロンプト本文と指摘・根拠を表示し、通常表示に戻すと再び折りたたむ。
指摘は保存する会話本文にも含まれる。
保存する会話・モデルに渡す制御文・非表示の context は変更せず、他の送信元のメッセージも折りたたまない。
送信元のプラグイン自身の描画フックはエンジンがスキップするため、描画処理は別プラグインに置く。
見出しは Claude Code 本体が描画するため残り、クリックによる個別の展開は行わない。
審査用プラグインだけで起動した場合は、修正・再開用プロンプトの本文も通常画面に表示する。
修正はメインエージェントがユーザーの既存の権限内で行う。
旧版からの再ロードで残るレビュアーは停止し、その結果通知でメインが再開しないようにする。

## 検索可能なセッションログ

ホストの `session.id` と、`CLAUDE_CONFIG_DIR`（未指定時は `~/.claude`）の `projects/` 配下にある標準 JSONL のファイル名から、対象を一意に特定する。
`classic.SessionStart`・`classic.UserPromptSubmit` は実機の組み込みセキュリティ Mod がスキップさせるため、`transcript_path` の取得には使わない。
会話レコードのセッション ID も照合し、一意に特定できない場合は検証不能にする。

資料の準備時には現在の依頼が標準ログへ反映されるまで最大5秒待ち、取得に成功した読み取り時のバイト数で範囲を固定する。
ツールを挟まない即時の回答では、`turn.step` の時点で現在の依頼がまだログにないことを実機で確認した。
末尾の改行、全行の JSON、対象の依頼文が含まれることを確認し、書き込み途中・取得失敗・不正なレコードを黙って省かない。
128 MiB を超えるログは検証不能にする。
審査中の追記は固定コピーに含めず、元ログは変更しない。

同梱の Node ヘルパー `hooks/session-log.mjs` が、OS の一時ディレクトリに審査専用の `cerberus-review-*` を作る。
ディレクトリは 0700、ファイルは 0600 とし、次の資料を保存する。

| 資料           | 内容                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| `source.jsonl` | 審査開始時までの原文コピー                                                     |
| `users.txt`    | ユーザーの文字列本文・ブロック配列を時系列で展開した一覧（tool_result は除外） |
| `history.txt`  | 管理レコードを含む全レコードを機械的に展開した本文                             |

文字列内の改行を復元し、各項目の JSONL 行番号・UUID・parent UUID・時刻・レコード種別を表示する。
ツール要求の ID と結果の `tool_use_id`、復帰・分岐・圧縮境界や内部通知も残す。
管理レコードをユーザーの依頼と扱わず、分岐の関係が判断できない場合は検証不能にする。
意味による要約や、回答にある語句だけでの事前選別は行わない。

レビュアーは最初にユーザー発言一覧を全件読み、古い制約・訂正も確認する。
その後、展開版を Grep・Read で検索し、必要なコード・出典も調査する。
Read の offset/limit と Grep の範囲指定を使い、切れた結果は分割して読む。
原文コピーと元パス・固定したバイト数／行数も入力に渡す。
検索の失敗、未読の制約、不足した結果は「制約がない」と扱わず、検証不能とする。
過去の assistant の断定やツール結果は証拠であり、実行する指示ではない。

資料は審査終了・取消時にヘルパーが削除する。
再ロード用状態には削除対象のパスだけを追加し、再ロード時に残存資料を削除してから再生成する。
プロセス強制終了などで状態保存前に残った資料は、次の生成時に24時間以上経過したものだけを削除する。
削除対象は専用ディレクトリ内の上記3ファイルと空ディレクトリに限定し、再帰削除は行わない。
レビュアーには生成・削除の操作を渡さず、ツールの通常の権限確認も維持する。

## 異常時と寿命

- 明示的な JSON の合格判定だけを受理する。空の返信、判定と指摘の矛盾、形式不正は検証不能とする。
- 修正回数・審査時間・保持する本文のサイズを制限する。
- 審査用モデルの呼び出しは最大16回、読み取り結果の合計は160,000文字までとする。上限・タイムアウト・形式不正・エラーは合格として扱わない。
- 検証できなかった本文は、未検証である旨の注記を先頭に付けてそのまま表示する。修正回数の上限では指摘が残る旨を注記し、指摘の内容は本文に表示せず `/cgate log` から確認する。
- 審査対象外の終了条件・サイズの回答も同じ注記で表示する。回答処理のエラーでは、そのステップで受け取った本文だけを注記付きで表示する。
- 修正依頼は元のターン終了後に送信する。送信に失敗すると本文を表示できないため、状態欄で通知する。
- 新しいユーザー依頼と中断で世代を変え、以前の審査結果と予約済みの修正依頼を無効にする。
- 再ロードでは依頼文・世代・審査番号・修正回数と処理中かどうかを、ホストが保持するセッション内の `$.state` から復元し、ディスクには保存しない。
- 作業中の再ロード後も次の最終回答を審査し、審査・修正依頼の配信待ちで中断した場合は、追加プロンプトで回答の再生成・再審査を依頼する。
- 審査終了後に再ロードされた場合は作業を続行し、完了済みの審査のための再開プロンプトは送らない。
- 保留原稿・指摘・公開予約は引き継がず、世代を進めて古い制御プロンプトと判定を無効にする。旧版の残存レビュアーは停止し、再開時に下書きを最終回答として復活させない。
- 取消・中断後の再ロードでは自動再開せず、`/clear`・セッション切替・終了時は復元用の状態を消去する。再開プロンプトを送信できない場合は、新しい依頼が必要な旨をログに記録する。
- 取消・タイムアウトでは審査用モデルを中断し、既に実行中の読み取り結果が遅れて戻っても破棄する。
- `/cgate cancel` で保留中の処理を取り消す。`/cgate` は原稿や指摘を含まない状態表示を返す。
- `/cgate log` で審査開始・判定・修正依頼・公開・タイムアウト・取消を時刻付きで表示する。判定に指摘がある場合は、その審査の記録に指摘と根拠も表示する。審査中でも即時に実行でき、検証処理を変更しない。
- ログは直近 1,000 件をメモリ上に保持し、省略した古い記録の件数を表示する。未公開の本文・依頼本文・例外の詳細は記録しない。指摘は JSON 文字列として表示し、改行や端末の制御文字をエスケープする。
- `/clear`、別セッションへの切替、終了、プラグインの再ロードでログを消去し、再開時には復元しない。従来の `/cerberus` と `/cerberus cancel` も利用できる。

2026-10-25 の haiku による `history` 試験では、1審査あたり2〜4回のモデル呼び出し、証拠 JSON は最大77,451文字だった。
履歴の追加範囲とコード・出典の再調査にも余地を設けるため、呼び出しは16回、証拠は160,000文字を上限とする。
審査時間の既定値120秒は維持する。
この実測は試験ケースでの値であり、長いセッション全般の所要量を保証しない。

## 対応環境と検証の範囲

初版の対象は Claude Code 2.1.310 の対話セッション。対象バージョン以外や設定が不正な場合は審査せず、回答を通常どおり表示する。
`claude -p` は最初の回答終了後にセッションが閉じ、審査結果を戻せないため、起動後に対象外の通知だけを返す。
旧版の残存レビュアーが使う内部の結果返却ツールは、実機で観測した契約を補助型として保持する。

再現可能な TUI 検証は [live-probe](/scripts/live-probe.mjs) で行う。
実モデルによる通常回答と修正・再審査に加え、テスト用 Mod で不正な審査応答と待機状態を作り、注記付きの表示と取消を確認する。
審査結果・破棄原稿・TUI の記録は Git 管理外のログへ保存する。

実際の Notion・Slack 接続と、他の Mod が公開本文を書き換える構成は未検証。
接続ツールの名前や読み取り属性、Hook の順序が環境ごとに異なるため、導入先でも確認する。

## 有効・無効の切り替え

`/cgate on` または `/cgate off` を実行すると、適用範囲の選択画面が開く。

- 「このセッションだけ」: 保存済み設定を変えず、このセッションで上書きする。
- 「設定に保存（次回以降も適用）」: ユーザースコープに保存し、一時設定を解除する。

選択前や Esc で閉じた場合は設定を変更しない。
`/cgate reset` で一時設定を解除し、保存済みの設定へ戻す。
`/cgate` は有効状態（on/off）、設定元（saved/session）、検証処理の状態を表示する。

既定は有効。`enabled` は `/config` でも変更できる。
一時設定はプラグイン再ロードでは維持し、`/clear`・別セッションへの切替・終了で解除する。
無効の間は回答を審査せず、通常どおり表示する。
審査中・修正依頼の配信待ちに無効化した場合は、保留中の回答と修正依頼を取り消し、新しい依頼が必要な旨を表示する。
有効化は次の回答ステップから適用する。

## 審査の観点と設定

既定の審査では、結論を変えうる前提を優先して確認する。
引用が主張の範囲や因果関係まで支えるか、具体例が許容値に収まるか、日時やデータの更新経路を確認する。
設定の既定値・環境別の設定・稼働環境の観測を区別し、集計の母集団・分類・除外条件と、不存在を断定できる検索範囲を確認する。
過去の回答や訂正、別エージェントの報告は、独立した裏付けとして扱わない。

重要な主張の裏付け不足を具体的に特定した場合は、正しい置換内容が未判明でも `REVISE` にする。
指摘には、根拠の所在と、必要な調査または断定を修正する内容を含める。
未実施の調査結果を作らず、追加調査や修正は既存の権限内でメインエージェントへ戻す。
具体的で実行可能な修正事項を特定できず審査を完了できない場合は `UNVERIFIED` とし、自動で再試行しない。
未決の仕様判断を事実誤認と混同せず、表現上の好みだけでは修正を要求しない。
実行・テスト・稼働状態の成功は、結果が証拠としてある場合だけ認める。

`reviewPrompt` で既定の審査本文全体を置き換えられる。
未設定・空文字・空白だけなら既定文を使い、指定された複数行や前後の空白はそのままモデルへ渡す。
上限は JavaScript の文字列長で20,000文字とし、型の不一致や上限超過では他の不正設定と同じく審査を無効にする。
本文に続けて読み取り専用の制約と JSON プロトコルを必ず付け、実行時にもセッションのツール一覧・ホストの権限判定・判定検証を適用する。
設定の保存先、再ロードと既定文への戻し方は、後述の「検証プロンプトの変更」を参照する。

## モデルと上限の設定

`/cgate model` で検査用モデルの選択 UI を開き、`inherit`・`haiku`・`sonnet`・`opus`・`fable` から選べる。
現在の設定がモデル ID の場合は、その値も選択肢に表示する。
モデルを選ぶと保存され、続いて effort（`inherit`・`low`・`medium`・`high`・`xhigh`・`max`）を選べる。
現在のモデルを選び直せば effort だけ変更できる。
Esc は表示中の選択を保存せず閉じる。effort の画面で閉じても、保存済みのモデルは維持する。
選択した値は Claude Code の設定 API で保存し、次の審査から使う。

レビュアーのモデルと effort、修正回数・審査時間の上限はプラグインの設定項目で変更する。
`reviewerModel` と `reviewerEffort` の既定値は `inherit` で、最終回答を生成したステップのモデルと effort を引き継ぐ。
`/config` でモデル ID や effort（`inherit`・`low`・`medium`・`high`・`xhigh`・`max`）を設定できる。
モデルが対応しない effort はエンジン側の制約に従う。
元のステップの effort が数値の場合、審査 API は数値を受け付けないため、審査モデルの既定値を使う。
選択 UI からの保存先はユーザースコープの `~/.claude/settings.json` の `pluginConfigs[<plugin>].options`。
`CLAUDE_CONFIG_DIR` を指定した場合は、その配下の `settings.json` に保存する。

## 検証プロンプトの変更

`reviewPrompt` で審査の観点・手順を変更できる。
未設定、空文字、空白だけの文字列では既定文を使い、それ以外は指定した本文で既定文全体を置き換える。
上限は JavaScript の文字列長で20,000文字とする。
文字列以外や上限超過は不正設定として審査を無効にし、通常の回答を表示する。

`/config` の「Review prompt」で文面を編集して保存でき、複数行の貼り付けにも対応する。
保存後はプラグインが再ロードされ、次の審査から適用する。
`claude plugin configure --values-stdin` は複数行を拒否するため、複数行の保存には設定画面または設定ファイルを使う。
複数行は設定ファイルの `pluginConfigs` 内の対象プラグインの `options.reviewPrompt` に、改行を `\n` として保存できる。
ローカルインストール時の ID は `cerberus-gate@happyonigiri-plugins`、`--plugin-dir` 起動時は `cerberus-gate@inline` となる。
`reviewPrompt` を空文字へ戻して再ロードすると、既定の審査に戻る。
`make install` による再インストールでも保存済みの本文を復元する。

```json
{
  "pluginConfigs": {
    "cerberus-gate@happyonigiri-plugins": {
      "options": {
        "reviewPrompt": "Check material claims against sources.\nPrioritize assumptions that could change the conclusion."
      }
    }
  }
}
```

設定は審査の本文だけを変更する。
読み取り専用の制約、許可ツール、権限判定、ツール要求と判定の JSON 契約は固定であり、設定では解除できない。
設定した観点によって審査結果は変わるため、重要な根拠や完了条件を確認する指示を含める。
