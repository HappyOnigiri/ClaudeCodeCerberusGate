# 回答検証の仕組み

## 表示と修正の流れ

```text
メインの最終回答案
  → turn.step で本文を保持（画面には審査中の状態だけを表示）
  → 読み取り専用レビュアーが依頼・会話の証拠・実ファイルを照合
      ├─ PASS       → 制御プロンプト → 保持した本文をモデルに書き直させず公開
      ├─ REVISE     → 制御プロンプトの非表示 context に指摘と未公開原稿を添付
      │                → メインが修正 → 新しい最終回答案を審査
      └─ UNVERIFIED → 本文を公開せず、検証を完了できなかった旨だけを表示
```

エンジンは空の応答を再生成することがあるため、保留時は短い状況文を返す。
下書きの断片は表示・通常の assistant 履歴へ流さない。
ツール実行を伴うステップはメインの作業を続けるために通す。審査対象は最終回答本文であり、途中の作業説明ではない。

## 読み取り専用の境界

レビュアーには組み込みの読み取り・検索ツールと、設定で明示された MCP ツールだけを渡す。
Bash、ファイル編集、外部サービスへの書き込み、別エージェントの起動は許可しない。
MCP は完全一致の名前で指定し、実行時に `isReadOnly=true` が報告される呼び出しだけを通す。
この情報がない呼び出しは拒否し、ユーザーや組織の既存の権限判定も維持する。

エンジン内部の審査結果返却は、調査用ツールとは別の制御として扱う。
結果は Mod 内で受け取り、親へ届く通知本文を定型文に置き換える。
自分のレビュアーの通知を通常の追加依頼として処理しないことで、不要なメイン再開を防ぐ。
追加プロンプトと、キャンセル・タイムアウト時のレビュアー停止も制御として行う。

## 異常時と寿命

- 明示的な JSON の合格判定だけを受理する。空の返信、判定と指摘の矛盾、形式不正は検証不能とする。
- 修正回数・審査時間・保持する本文のサイズを制限する。上限やエラーで未検証本文へフォールバックしない。
- 新しいユーザー依頼と中断で世代を変え、以前の審査結果と予約済みの公開処理を無効にする。
- 再ロードでは保留原稿を引き継がず、自分の残存レビュアーを停止する。再開時に下書きを最終回答として復活させない。
- `/cerberus cancel` で保留中の処理を取り消す。`/cerberus` は原稿や指摘を含まない状態表示を返す。

## 対応環境と検証の範囲

初版の対象は Claude Code 2.1.310 の対話セッション。対象バージョン以外では検証不能として本文を公開しない。
`claude -p` は最初の回答終了後にセッションが閉じ、審査結果を戻せないため、起動後に対象外の通知だけを返す。
エンジンが自動で使う内部の結果返却ツールは生成型に含まれないため、実機で観測した契約を補助型として保持する。

再現可能な TUI 検証は [live-probe](/scripts/live-probe.mjs) で行う。
実モデルによる通常回答と修正・再審査に加え、テスト用 Mod で不正な審査応答と待機状態を作り、公開の抑止と取消を確認する。
審査結果・破棄原稿・TUI の記録は Git 管理外のログへ保存する。

実際の Notion・Slack 接続と、他の Mod が公開本文を書き換える構成は未検証。
接続ツールの名前や読み取り属性、Hook の順序が環境ごとに異なるため、導入先でも確認する。
