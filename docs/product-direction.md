# プロダクト方針

開発言語は TypeScript とする。

## 目的

Claude Code の最終回答をユーザーに表示する前に Side Agent が根拠を検証し、必要な修正と再検証を済ませた本文だけを表示する Mods を作る。ユーザーが未検証の回答と後から届く訂正を読み比べる負担を減らし、検証を通過した最終版を一度読むだけで済む体験を目指す。

### 解決したい課題

従来の表示後レビュー方式では、回答の表示後に Side Agent が検証し、指摘があれば追加ターンで訂正する。この方式では、最初の回答を読んだ後に、訂正箇所を把握して理解を更新する必要がある。回答品質を改善するだけでなく、この読み直しと判断の負担を減らすことを目的とする。

### 目指す動作

```text
最終回答案を生成 → 本文を保留 → Side Agent が根拠を検証
                                  ├─ 合格 → 検証済みの本文を表示
                                  ├─ 要修正 → 最終回答を保留したまま
                                  │           メインエージェントへ追加プロンプト
                                  │           → メインが修正 → 回答案を再検証
                                  └─ 検証不能 → 未検証本文を公開せず状況を通知
```

- 回答のもっともらしさだけでなく、ユーザーの依頼・制約、実際のコード、ツールの実行結果、出典との整合性を確かめる。
- 修正前の本文やレビュー指摘を通常の回答欄へ流さず、ユーザーに見せる前に修正と再検証を完結させる。
- 合格した本文をそのまま公開し、検証後の書き直しで未検証の内容が混入することを防ぐ。
- 検証のエラーやタイムアウトを合格として扱わず、未検証本文の自動公開を防ぐ。
- 通常のツール実行やユーザーへの質問を維持し、検証中は短い状況表示で進行を伝える。

### Mod とメインエージェントの役割

Mod と Side Agent が検証のために行う操作は、副作用のない読み取り・検索に限定する。ファイルの READ、Notion や Slack の検索などで根拠を確認し、自らコードや外部サービスのデータを変更しない。

レビューで修正が必要と判定した場合、Mod はユーザー向けの最終回答を出さず、指摘と修正依頼を追加プロンプトとしてメインエージェントに送信する。回答本文やコードなどの修正はメインエージェントが行い、Mod は修正後の回答案を再検証する。追加プロンプトの送信は、修正をメインエージェントへ戻すための制御として行う。

メインエージェントによる修正は、ユーザーが許可した作業範囲と既存の権限に従う。レビュー指摘を、追加の変更権限として扱わない。検証に合格するまで、修正前・修正途中の最終回答は公開しない。

### 初版の実装と今後の検討

メイン Agent の最終回答本文を、1 つの読み取り専用レビュアーで検証する。
レビュアーは既定でメインのモデルを引き継ぎ、設定で変更できる。
修正回数と審査時間には設定可能な上限を設け、上限に達した回答を合格扱いにしない。
実装した流れと対応環境は [回答検証の仕組み](/docs/answer-gate.md) に記載する。

動作の経過は `/cgate log` で確認できる。
未公開の回答案やレビュー指摘は表示しない。
複数レビュアーの利用、接続先ごとの検索ツールの設定、他の Mods との併用は今後具体化する。
